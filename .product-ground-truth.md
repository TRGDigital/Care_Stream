# CARESTREAM PRODUCT GROUND TRUTH

Factual, code-verified reference of what CareStream actually does as of 2026-06-08. Compiled from the Prisma schema, API services/routes, and the Next.js web app. Legend: **REAL** = fully wired and working in code; **PARTIAL** = exists but limited/stubbed/depends on config; **ABSENT** = not found in code.

Brand in code: "CareStreamAI" (domain carestreamai.co.uk). Stack: Express + TypeScript + Prisma API; Next.js 14 web app. DB: Supabase Postgres + Pinecone vectors. Multi-tenant (`tenant_id` on every table, RLS).

---

## 1. Channels — how staff interact

The same RAG query pipeline (`apps/api/src/services/rag/query.ts`) backs all channels.

| Channel | Status | Evidence |
|---|---|---|
| **Web chat portal** | **REAL** | `apps/web/src/app/(portal)/chat/page.tsx` — full chat UI with category picker, session history, follow-ups, feedback. |
| **Email** | **REAL** | Inbound via SendGrid Inbound Parse to `policies@{slug}.carestreamai.co.uk` (`services/email/inbound.ts`); outbound via SendGrid (`services/email/outbound.ts`). 7-day threaded sessions (`EmailSession`). Requires `SENDGRID_API_KEY` + inbound domain config. |
| **WhatsApp (text)** | **REAL** | Twilio webhook (`routes/whatsapp.ts` → `services/whatsapp/inbound.ts`). 24-hour sessions (`WhatsAppSession`). Quick-reply follow-up buttons via Twilio Content API. Sandbox (shared number + phone allowlist) and production (per-tenant `twilio_whatsapp_number`) paths both implemented. Requires Twilio env config. |
| **WhatsApp voice notes** | **REAL** | Audio downloaded from Twilio and transcribed with OpenAI **whisper-1** (`services/whatsapp/inbound.ts` `transcribeVoiceNote`), then run through the normal pipeline. Channel recorded as `voice`. |
| **Standalone phone/voice calls (PSTN, Twilio Voice)** | **ABSENT** | No TwiML voice-call handling. "Voice" only means transcribed WhatsApp audio notes. |
| **SMS** | **ABSENT** | No SMS handler. |

Notes for marketing: voice = WhatsApp voice notes only, not a phone-call IVR. All channels share the monthly query limit; every message (incl. follow-ups and voice notes) is one query — this matches the pricing FAQ copy.

## 2. AI models actually used

Verified from model-ID strings in service code:

- **Primary chat/RAG generation:** Anthropic **claude-sonnet-4-5** (`services/ai/claude.ts`, default, overridable via `CLAUDE_MODEL`). Used for policy/CQC/audit/training/business-continuity chat answers and full-policy formatting (Prompt B). — **REAL**
- **Intent classification:** Anthropic **claude-haiku-4-5-20251001** (`services/intent/classifier.ts`). — **REAL**
- **Translation (outbound multi-language):** **claude-haiku-4-5-20251001** (`lib/translate.ts`). — **REAL**
- **Regulation-coverage gap analysis:** **claude-haiku-4-5-20251001** (`services/analytics/regulation-coverage.ts`). — **REAL**
- **Embeddings:** OpenAI **text-embedding-3-small** (1536-dim) for both ingestion and query (`services/rag/embedder.ts`). — **REAL**
- **Vector DB:** **Pinecone**, per-tenant namespaces incl. handbook chapter index (`services/vector/pinecone.ts`). — **REAL**
- **WhatsApp button labels:** OpenAI **gpt-4o-mini** (`services/whatsapp/inbound.ts`). — **REAL**
- **Voice transcription:** OpenAI **whisper-1**. — **REAL**
- **Training cover/section images:** OpenAI **gpt-image-1**, 1024×1024 (`services/training/moduleImage.ts`). — **REAL**

So: a multi-model stack (Claude Sonnet + Haiku, OpenAI embeddings/whisper/gpt-image/gpt-4o-mini). Marketing claiming "powered by Claude" is accurate for the core answering; embeddings/images/transcription are OpenAI.

## 3. Policies — upload, management, distribution, multi-language

- **Upload + ingestion:** **REAL**. `routes/policies.ts`, RAG ingestion (`services/rag/ingestion.ts`, chunker, extractor, stripper, toc-detector). Stored in S3 (`services/storage/s3.ts`), embedded into Pinecone. `Policy` model has versioning, status, content-hash dedupe, sections/tags, review-interval reminders, supersede chain.
- **Categories:** internal_policy and staff_handbook (`document_category`). Handbooks get two-stage chapter-index retrieval (`handbook_metadata`, chapter namespace). — **REAL**
- **Distribution / Q&A:** **REAL** — staff query policies across all channels; answers cite policy name + version.
- **Multi-language answering:** **REAL**. `services/language/detector.ts` (franc, ISO 639-3) + `lib/translate.ts`. Per-policy translations cached (`PolicyTranslation`, `TranslationCache`). Full policy-read/induction sessions support a `lang` field.
- **Full-policy retrieval:** **REAL** — "send me the full policy" path downloads S3 text and reformats via Prompt B.

## 4. Staff Training

- **Standard (platform) modules vs tailored (tenant) modules:** **REAL**. `TrainingModule` with `tenant_id = null` (shared template) vs tenant copy. `source` = `manual` | `ai_generated`.
- **AI module generation (teach-then-assess):** **REAL**. `services/training/moduleGenerator.ts` grounds an annual refresher in the tenant's own policies (RAG) + anonymised policy seeds; produces learning sections, scenarios, in-section checks and a 20-question assessment bank. Output is a **draft** needing admin approval (`approved` flag, `approved_by/at`).
- **Credits / billing:** **REAL**. `AiCreditLog` tracks billable actions (`training`, `cqc_questions`, `training_questions`) vs tracked-only (`translation`, `audit_recs`, `remediation`). `Plan.monthly_ai_credit_limit` enforces a monthly quota. Tailored training generation consumes a credit (matches memory: "standard (free) vs tailored (1 credit)").
- **Cover images:** **REAL**. gpt-image-1 illustrations stored in S3 (`illustration_key`).
- **Delivery / quizzes / spaced repetition:** **REAL**. `TrainingDeliveryRule` + `TrainingSendLog` (scheduled, manual, return_to_work, post_incident, quizme, spaced_repetition); WhatsApp/email answer interception (`services/training/conversation.ts`, `proactive.ts`).
- **Certificates / CPD / renewals:** **REAL** (fields present). `TrainingEnrollment.certificate_url`, `renewal_count`, expiry; modules carry `pass_mark`, `cpd_accredited`, `independently_reviewed`, `duration_minutes` (CPD hours), practical sign-off, learner evaluation (confidence/usefulness).
- **External specialist review/attestation:** **REAL**. `ModuleReviewLink` (password-protected, snapshot-frozen sign-off links) + public review routes (`training-review-public.ts`).
- **Remediation ("Learn & retry"):** **REAL**. `RemediationLesson` / `RemediationAttempt` cached per concept+language.

⚠️ Marketing caution: `cpd_accredited` / `independently_reviewed` are **flags an admin/reviewer sets**, not evidence of an actual external CPD accreditation body. Claiming "CPD-accredited" as a blanket product fact would over-claim unless real accreditation exists.

## 5. Care Audits

- **Guided digital audits:** **REAL**. `AuditTemplate` → `AuditSection` → `AuditQuestion` (yes_no, yes_no_na, findings, free_text); platform-seed templates + tenant-custom. `AuditRun`/`AuditAnswer` capture results. Supports shift-based (day/night) and room-by-room runs.
- **WhatsApp conversational audits:** **REAL**. `services/audit/conversation.ts` walks a user through an audit step-by-step over WhatsApp (yes/no/n-a/findings, strengths, improvements, deadline). Triggered by "start audit".
- **AI recommendations:** **REAL**. `routes/audits.ts` calls Claude to generate `ai_recommendations` from run answers + strengths/improvements; stored on `AuditRun` and chattable via the "Auditing" portal category.
- **Audit seeds:** **REAL**. Platform audit-seed templates managed at `(platform)/platform/audit-seeds`.

## 6. CQC & Compliance

- **CQC report upload + chat:** **REAL**. CQC inspection reports are uploaded as policies with `document_category = cqc_report`, embedded into Pinecone. The portal "CQC Compliance" category (`cqc_report` path in query.ts) does **multi-source retrieval**: the uploaded CQC report + internal policies + handbook + CQC framework seeds (`CqcSeed`) + approved knowledge entries + regulations. The system prompt frames Claude as a "CQC Compliance Director" that helps draft factual-accuracy challenges and identify gaps. — **YES, users can genuinely chat with their inspection reports.**
- **CQC framework knowledge base:** **REAL**. `CqcSeed` (Safe/Effective/Caring/Responsive/Well-led) with inspector_focus, evidence_expected, rating_indicators. Managed at `(platform)/platform/cqc-seeds`.
- **CQC staff questions (mock-inspection):** **REAL**. `routes/cqc-staff-questions.ts` + `CqcStaffQuestion`/`CqcStaffDelivery`. AI generates inspector-style questions + model answers per KLOE domain; questions are AI-rephrased and delivered to staff (default channel `portal`, also whatsapp/email); staff answers are AI-evaluated (0–100 score + feedback), with retry tracking (`first_score` vs latest). 20 seed questions ship in code.
- **Readiness/coverage tracking:** **REAL** (PARTIAL scope). `RegulationCoverage` computes covered/partial/gap per regulation via semantic retrieval + Claude judgement (Policy Gaps page). `analytics/cqc-report` admin page + analytics route exist.

## 7. CQC Report Chat (explicit)

**REAL.** Yes — once a CQC report is uploaded (category `cqc_report`), staff/managers chat with it through the portal/email/WhatsApp. It is not a separate engine; it's the `cqc_report` branch of the RAG pipeline that cross-references the report against the home's policies and the CQC framework. Marketing page exists at `(marketing)/cqc-report-chat`.

## 8. Business Continuity

- **Status: PARTIAL** — it is a chat surface over knowledge entries, **not** a dedicated BC plan-builder.
- `query.ts` has a `business_continuity` branch that answers from approved `KnowledgeEntry` rows tagged `knowledge_category = 'business_continuity'` (Postgres, no vector search). The portal exposes a "Business Continuity" category.
- There is **no** structured BC-plan data model (no scenario/contingency/emergency-contact entities). If no BC knowledge entries are added, the assistant returns a "no entries yet" note.
- Marketing caution: it's "ask questions about your business continuity info" backed by manually-curated Q&A, not an automated continuity-plan generator. Marketing page at `(marketing)/business-continuity`.

## 11. Regulatory knowledge base (external regulations)

- **REAL.** `ExternalRegulation` (platform-level, shared read-only): official_name, also_known_as, summary, care_home_context, care_company_interaction, practical_meaning, source_urls, optional Pinecone vector. Surfaced in RAG answers when a regulation is detected (`regulation-detector.ts`).

## 12. Multi-language

- **REAL.** Detection: franc, ISO 639-3, threshold 0.5, English-adjacent (Scots/Afrikaans/Old-English) coerced to English (`language/detector.ts`).
- ~60 languages mapped to display names, including UK-care-common ones (Polish, Romanian, Portuguese, Filipino/Tagalog, Yoruba, Hindi, Malayalam, Shona, etc.).
- Three interaction patterns: English→English; English + explicit request ("reply in Polish")→requested language; non-English→detected language. Staff can also set `first_language`/`second_language` and force a reply language in the portal.
- Translation via Claude Haiku, cached (`TranslationCache`, `PolicyTranslation`). Translation is tracked (non-billable) in `AiCreditLog`.
- Caveat: detection relies on franc, which is unreliable on short text — code explicitly defaults low-confidence to English and flags for review. "60+ languages" is supportable; "guaranteed accurate auto-detection" would over-claim.

## 13. Billing / credits / pricing

- **Plans:** `Plan` model — Starter / Professional, `price_monthly_pence`, `monthly_query_limit`, caps (`max_policies`, `max_staff_users`, `max_handbooks`, `max_manual_knowledge_entries`), feature flags (`has_advanced_analytics`, `has_cqc_report`, `has_gap_detection`), `monthly_ai_credit_limit`. Marketing pricing page shows **£49/mo Starter (500 queries)** and **£129/mo Professional (5,000 queries)** plus an Enterprise mention. — model **REAL**, prices live on marketing page.
- **Query limit enforcement:** **REAL** (`lib/plan-limits.ts`, `checkQueryLimit` called on every channel before the pipeline; over-limit returns a friendly block message).
- **AI credits:** **REAL** — billable vs tracked-only metering via `AiCreditLog` + `monthly_ai_credit_limit`.
- **Stripe:** **PARTIAL**. Webhook handler is fully implemented (`services/billing/stripe.ts`: checkout.session.completed, invoice.paid, payment_failed, subscription.deleted → updates `subscription_status`) and Customer Portal session creation works. **BUT** `/billing/summary` and `/billing/invoices` return **stubbed nulls/empty arrays** (next_billing_date, invoices etc. are TODO placeholders), and there is **no Stripe Checkout session creation** in the codebase — so self-serve subscription sign-up/checkout is not wired end-to-end yet. Default tenant `subscription_status` is `trialling`.
- Marketing caution: "14-day free trial, no card required" is consistent with trialling default, but live self-serve paid checkout is not fully implemented in code.

### Known operational caveats (from project memory, not feature claims)
- BullMQ workers and the setTimeout-based renewal scheduler do **not** run on Vercel serverless — background jobs need a persistent host. So "scheduled" training delivery / reminder cron behaviour may not fire in the current Vercel deployment without a separate worker host. (Some scheduling moved to `routes/cron.ts` + Vercel cron.)
- Recurring prod DB connection exhaustion on direct port 5432 (durable fix = transaction pooler 6543, pending).

## Summary of likely marketing mismatches

**Could OVER-claim if stated as product facts:**
- "Voice assistant / phone support" → only WhatsApp voice-note transcription, no PSTN/IVR. (ABSENT)
- "Business continuity planning" → only Q&A chat over manually-added entries, no plan-builder/data model. (PARTIAL)
- "CPD-accredited / independently reviewed training" → admin-set flags, not proof of external accreditation. (verify externally)
- "Self-serve Stripe checkout / live billing dashboard" → webhook + portal exist, but checkout creation and billing summary/invoices are stubbed. (PARTIAL)
- "Automatic language detection" → franc-based, explicitly unreliable on short text and defaults to English. (works but hedged)

**Could UNDER-claim (real, strong features marketing might miss):**
- True multi-channel parity (web, email, WhatsApp text + voice notes) on one RAG engine.
- WhatsApp conversational audits and conversational training quizzes with AI evaluation.
- CQC mock-inspection staff Q&A with AI scoring + retry improvement tracking.
- AI training-module generation grounded in the home's own policies, with external specialist sign-off links.
- Per-query real AI cost + token/cache accounting and editable platform prompts with version history.
- WebMCP agent tools (AI agents can query policies / start audits with confirmation + audit logging).
