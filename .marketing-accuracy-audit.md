# CareStream Marketing Accuracy Audit
_Generated 2026-06-08. Compares marketing copy against code-verified product ground truth (`.product-ground-truth.md`)._

Scope: Homepage + all 8 "Our Services" mega-menu pages.
Legend: ❌ FALSE (feature absent / contradicts code) · ⚠️ OVERSTATED (partial/stubbed reality) · ❓ UNVERIFIABLE (stat/claim not checkable from code) · 🟡 MISSING (real strong feature not marketed).

---

## TIER 1 — Fix first: claims for features that DO NOT EXIST (❌ FALSE)

These describe functionality with no backing in the schema or API. Highest legal/credibility risk.

### Care Audits (`/care-audits`) — the worst offender
- **"Recommendations drawn from your own policies… links to the specific section"** (mockup: _"From your Medication Policy, Section 5.2…"_). The audit-completion prompt in `routes/audits.ts` is fed **only** the audit's own answers/strengths/improvements — **no policy RAG retrieval**. It cannot cite policies.
- **"Month-on-month trend analysis" / "recurring issue across multiple months" / "three consecutive audits → systemic issue."** The prompt analyses a **single run**; no prior runs are loaded or compared. No trend logic exists.
- **"Actions tracked to closure"** with owner / due date / status / completion date. There is **no action-item entity** — only free-text fields on `AuditRun`. No status, no owner, no closure tracking.
- **"Audits can be assigned to any staff member"** (_"Assigned to: Sarah Mitchell"_). `AuditRun` has only free-text `auditor_name`; no user assignment, no per-assignee routing. Reminders go to **all** admins/managers.

### Business Continuity (`/business-continuity`) — hero mockup is fabricated
- **The "BC Plan Coverage" hero card** ("4/6 scenarios", per-scenario Covered/Partial/Review status, "Plan last reviewed: 14 May 2026", "2 scenarios need updated procedures"). **None of this exists.** BC is only a plain-Postgres Q&A chat over manually-added `KnowledgeEntry` rows tagged `business_continuity`. There is no scenario model, no coverage scoring, no plan-review tracking, no gap analysis.
- **Source citations like "Source: BC Plan, Section 4.2."** No sectioned "plan" document exists; answers come from flat knowledge entries.

### CQC Staff Questions (`/cqc-staff-questions`)
- **Multiple-choice chat mockup** (A/B/C/D, "Reply A, B, C or D"). The product is **open-ended only** — staff submit free-text answers that Claude scores 0–100. The MCQ mockup misrepresents the core interaction.
- **"Automatic alerts when scores drop… practice questions automatically distributed."** No threshold/alert/auto-distribute logic exists anywhere. Delivery is always a manual admin action.

### CQC & Compliance (`/cqc-compliance`)
- **Hero "91 / 100" CQC Readiness score.** The product computes **no composite readiness score** (`/analytics/cqc-report` returns counts only; `RegulationCoverage` is per-regulation covered/partial/gap). This also directly contradicts the page's own (good) legal disclaimer.

### Care Policies (`/care-policies`)
- **"No document count limit… no file size cap. All plans include unlimited policy storage."** Contradicts `Plan` caps (`max_policies`, `max_handbooks` — Starter = 1 handbook, `max_manual_knowledge_entries`).
- **"Voice input via WhatsApp voice note _or chat portal_."** No in-portal voice capture exists.

### Homepage (`/`) & Care Policies — Voice
- **Voice presented as a standalone/in-app channel** (mic/REC/waveform UI, "Voice" tile peer to Email/Chat/WhatsApp). Real product: **voice = WhatsApp voice notes only** (whisper-1 transcription). No PSTN/IVR, no in-app voice assistant.

## TIER 2 — Overstated: real feature, exaggerated scope (⚠️)

- **"Business continuity plan" framing throughout** (`/business-continuity`): "queryable BC plan", "automatic gap detection", "scenario-based staff testing", "section-level query analytics". Reality = manually-curated Q&A entries. Reframe away from a structured "plan".
- **Automatic language detection presented as flawless** (homepage, `/hr-policies`, `/care-policies`, `/staff-training`): franc-based detection is explicitly unreliable on short text and defaults low-confidence to English. Keep "automatic"; drop "no selection required" absolutes.
- **Scheduled delivery / renewal reminders as guaranteed-automatic** (`/staff-training`: "90, 30, 7 days"; `/care-audits`: monthly reminders; `/care-policies`: review reminders). Features exist in code, but ⚠️ the setTimeout/BullMQ schedulers **don't run on Vercel serverless** without a worker host — verify cron actually fires before promising automatic delivery. Also the exact "90/30/7" cadence and the audit "monthly" reminder (code excludes monthly) need verification.
- **"50+ regulatory frameworks pre-loaded"** (homepage, `/care-policies`): `ExternalRegulation` is **synced from a Google Sheet**, so the live count is data-dependent and unverifiable. Avoid the hard number.
- **Knowledge base "automatically extracts named individuals / schedules / local procedures"** (`/care-policies`): no fact-extraction engine; retrieval happens at query time + manual knowledge entries.
- **CQC report answers "drawn purely from your report"** (`/cqc-report-chat`): actually multi-source (report + policies + handbook + CQC seeds + regulations) — this understates a strength.
- **"Multilingual access = Equality Act 2010 compliance"** (`/cqc-compliance`): it's usage evidence, not a compliance determination.
- **WhatsApp "works even when your internet is down"** (`/business-continuity`): misleading — Twilio + API + Postgres all need connectivity.
- **"50+ languages"** should be **"60+"** to match ground truth (`/hr-policies` under-claims and is internally inconsistent).
- **"Auto-compiled monthly CQC Readiness Report PDF"** (homepage, `/care-policies`): verify the PDF export + monthly cadence exist; gap snapshots are daily.

## TIER 3 — Unverifiable stats & claims needing substantiation (❓)

- **Latency stats repeated everywhere:** "under 30 seconds" / "30 sec average" (homepage, `/hr-policies`, `/care-policies`, `/business-continuity`), "under 60 seconds" indexing (`/cqc-report-chat`), "3 min" / "2 min" WhatsApp answer times (`/staff-training` — also self-contradicts its own "10 seconds"). No latency instrumentation in code. Soften to "in seconds" or back with real telemetry.
- **Placeholder testimonials** rendered literally as `[Testimonial, …]` on the homepage under "Trusted by care professionals." Replace with real attributable quotes or remove before launch.
- **Market stats** (homepage): "1 in 3 night-shift policy questions go unanswered", "30%+ care workers born outside UK", "150+ languages in UK care", "70% forgotten in 24h". Cite sources.
- **Security/infra claims:** "AES-256", "encrypted at rest", "never used to train AI models", "UK data residency on Pro/Enterprise" (`/care-policies`, `/cqc-report-chat`). Plausible (S3/Supabase/provider defaults) but not in app code — confirm config + provider terms before asserting.
- **"Set up in under an hour / up and running the same day"** (homepage): not code-verifiable.

## TIER 4 — Missing opportunities: real, strong features under-marketed (🟡)

- **WhatsApp conversational audits** — send "audit" on WhatsApp and it walks you through each question step-by-step, syncing to the same run (`services/audit/conversation.ts`). Entirely absent from `/care-audits`. Big differentiator.
- **Shift-based (day/night) and room-by-room audit runs** — real (`AuditRun.shift`, `room_number`), unmentioned.
- **AI-generated training modules grounded in the home's own policies** (teach-then-assess, draft→approve, standard free vs tailored 1-credit) + **external specialist sign-off links** (`ModuleReviewLink`) + **"Learn & retry" remediation**. `/staff-training` never mentions its strongest features.
- **CQC report multi-source cross-referencing** + **drafting factual-accuracy challenges** + **email/WhatsApp access** — all real, missing from `/cqc-report-chat`.
- **CQC retry-improvement tracking** (first_score vs latest) and **AI free-text scoring** — undersold on `/cqc-staff-questions` while MCQ/alerts are oversold.
- **Two-stage chapter retrieval for large handbooks** — real differentiator missing from `/hr-policies`.
- **Homepage body** sells only policy access; flagship Training / Audits / CQC Staff Questions / Onboarding / CQC-report-chat are teased in the hero but never explained.
- **Answers cite policy name + version** and **approved-knowledge gate** (only vetted content served) — strong trust signals barely surfaced.

## Cross-cutting themes (fix once, apply everywhere)
1. **Voice** → always "WhatsApp voice notes", never a standalone/portal/phone channel.
2. **Latency** → stop quoting "30 seconds"; use "in seconds" or real telemetry.
3. **Scheduling** → confirm cron/worker fires on Vercel before promising automatic sends/reminders.
4. **Mockups** → several heroes show metrics the product doesn't compute (91/100, BC scenario coverage, MCQ). Align mockups to real outputs.
5. **Plan limits** → stop implying "unlimited"; reflect `max_policies` / `max_handbooks` / credit caps.
6. **Under-selling** → Training AI-generation, WhatsApp audits, CQC retry-scoring, multi-source CQC chat are real and strong — market them.
